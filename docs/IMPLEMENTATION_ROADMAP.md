# نقشه راه پیاده‌سازی

## انجام‌شده در این مرحله
- بررسی مخزن و ثبت محدودیت معماری فعلی.
- ایجاد SPA فارسی RTL با داشبورد responsive.
- افزودن فهرست، جست‌وجو، فیلتر وضعیت، فرم افزودن ملک، نوار اعلان و ناوبری بخش‌ها.
- استفاده از هویت تصویری موجود و فونت Vazirmatn؛ داده‌های عملیاتی در پایگاه داده هستند و نمونه‌ها به برنامه وصل نیستند.
- ساخت موفق Production bundle با `npm run build`.
- تکمیل مرحلهٔ فایلینگ در محدودهٔ پیش‌نمایش: ساخت، ویرایش، بایگانی/بازگردانی، فیلتر وضعیت و خروجی CSV فارسی؛ اعتبارسنجی اعداد فارسی/عربی و تست منطق دامنه.
- اجرای چرخهٔ TDD برای عملیات فایل ملک: ۷ تست Vitest سبز.
- ایجاد API NestJS + Drizzle برای فایلینگ و CRM، اعتبارسنجی DTO، Supabase JWKS/tenant membership guards، مهاجرت‌های افزودنی/RLS و پروکسی توسعه Vite؛ بدون اتصال DB واقعی.
- افزودن CRM عملیاتی مشتریان: ثبت/ویرایش، جست‌وجو، فیلتر مراحل، بودجه‌ با واحد ارز روشن، بایگانی/بازگردانی و CSV؛ API با audit، کنترل دسترسی و RLS tenant/branch.
- افزودن پیگیری‌های CRM برای تماس/جلسه/بازدید ملک/یادآوری: API فهرست/ثبت/تکمیل/لغو، RLS و audit، فرم و فهرست فارسی متصل به API؛ شروع ثبت پیگیری با مشتری از ردیف دفتر CRM، انتخاب خودکار همان مشتری و نمایش کارهای باز نزدیک در داشبورد.
- افزودن پیوند تماس مستقیم `tel:` با تبدیل ارقام فارسی/عربی در دفتر مشتریان و صفحهٔ پیگیری.
- مهاجرت‌های نسخه‌بندی‌شده و checksum برای `0001` تا `0003`؛ runner با پوشه‌های migration و فایل `migration.sql` سازگار شده است و آزمون رفتار RLS در PGlite پوشش دارد.
- افزودن تست‌های DTO، قواعد دسترسی/قیمت، migration و پیگیری؛ در اعتبارسنجی فعلی ۴۸ تست سبز، شامل ۱۳ سناریوی RLS در PGlite؛ `npm run build:all` موفق و `npm audit --audit-level=moderate` بدون آسیب‌پذیری.
- ثبت پرامپت‌ها و skillهای منتخب در `docs/EXECUTION_PROMPT_PROPERTIES.md` و `docs/EXECUTION_PROMPT_BACKEND.md`.

## مراحل بعدی
1. انتخاب PostgreSQL و Supabase اختصاصی ملکینو؛ تأیید قابلیت‌های Node/PostgreSQL cPanel.
2. backup, DBA review, provisioning نقش‌های DB، اجرای کنترل‌شده migrationها و آزمون روی PostgreSQL واقعی.
3. end-to-end فایلینگ/CRM با کاربرهای واقعی و چند نقش، سپس استقرار staging روی cPanel.
4. تکمیل مدیریت مشتری-ملک و تجربه‌های task/appointment؛ افزودن آزمون UI/E2E برای جریان CRM و پیگیری.
5. معاملات/قراردادها، مجوزها و audit تکمیلی.
6. مالی/کمیسیون با Decimal، گردش تأیید و آزمون‌های حسابداری.
7. تقویم کامل، گزارش، بازاریابی و ادغام‌های واقعی.
8. E2E روی محیط اختصاصی، بررسی امنیت، backup/restore، observability و انتشار cPanel.

## وضعیت فعلی و گام بعد
فایلینگ و CRM پایه، شامل پیگیری تماس/جلسه/بازدید/یادآوری، به API/Auth پیکربندی‌پذیر متصل‌اند؛ فهرست، ثبت، تکمیل و لغو پیگیری‌ها و CRUD مشتری از backend استفاده می‌کنند. تست/build/audit فعلی سبز است، اما بدون env معتبر برنامه صفحهٔ راه‌اندازی نشان می‌دهد. هیچ API/DB واقعی در این workspace انتخاب نشده و migration روی PostgreSQL واقعی اجرا نشده است؛ اعلان خودکار، یادآوری زمان‌بندی‌شده و تقویم کامل هنوز پیاده‌سازی نشده‌اند.

مرحلهٔ بعد نیازمند پایگاه دادهٔ اختصاصی ملکینو و Supabase Auth همان پروژه است؛ PostgreSQL/Docker محلی در دسترس نیست و پروژهٔ ابری مشخص‌شده‌ای برای ملکینو نداریم. از تغییر پروژه‌های دیگر خودداری شد. پس از اتصال محیط، migration را در DB اختصاصی اعمال، membership provisioning را تعریف، API را اجرا و آزمون RLS/cross-tenant را با چند tenant/role انجام می‌دهیم.
