# گزارش بررسی فنی ملکینو

تاریخ بررسی: ۱۴۰۵/۰۸/۲۲

## وضعیت مخزن پیش از شروع
- مخزن شامل `README.md` (پرامپت محصول) و سه تصویر PNG برند بود.
- هیچ کد برنامه، وابستگی، پیکربندی Build، API، دیتابیس، احراز هویت یا تستی وجود نداشت.
- بنابراین معماری موجودی برای حفظ یا ارتقا وجود نداشت و هیچ داده عملیاتی/مشتری در مخزن مشاهده نشد.
- تصاویر مخزن: نشان مربع ملکینو، لوگوی افقی، و تصویر راهنمای هویت برند. نشان مربعی برای هویت نوار کناری و آیکون برنامه استفاده شده است.

## محدوده تحویل فعلی
رابط فارسی/RTL داشبورد و فایلینگ، Supabase Auth client و API adapter پیکربندی‌پذیر دارد. عملیات فایلینگ پس از ورود از API انجام می‌شود؛ داده نمونه و localStorage به‌عنوان fallback حذف شده‌اند. Backend NestJS/Drizzle شامل JWT/JWKS، tenant/branch guard، PostgreSQL migration و RLS است. هنوز هیچ DB یا پروژه Supabase اختصاصی انتخاب/وصل نشده؛ migration فقط در PGlite آزموده شده و اتصال production/E2E انجام نشده است. هدف استقرار cPanel در `docs/CPANEL_DEPLOYMENT.md` ثبت شده.

## محدودیت‌ها و ریسک‌ها
- API، Backend، Supabase Auth، RBAC، چندمستاجری و RLS در کد پیاده‌سازی و در سطح build/unit/PGlite آزموده شده‌اند، اما به هیچ DB یا پروژهٔ Supabase اختصاصی ملکینو متصل نیستند؛ این قابلیت‌ها را در محیط واقعی عملیاتی تلقی نکنید.
- فایلینگ، CRM مشتریان و پیگیری‌های تماس/جلسه/بازدید/یادآوری به API متصل‌اند، مشروط به پیکربندی محیط؛ اعلان خودکار، یادآوری زمان‌بندی‌شده و تقویم کامل هنوز فعال نیستند.
- معاملات، مالی، گزارش‌ها و اسناد در وضعیت نقشه‌راه هستند.
- تصاویر نمونه ملک از Unsplash بارگذاری می‌شوند؛ اتصال خارجی اختیاری است و برای اطلاعات حساس یا واقعی کاربرد ندارد.
- آزمون خودکار E2E/امنیتی و استقرار cPanel هنوز انجام نشده‌اند؛ migration فقط در PGlite آزموده شده است.

## پیشنهاد گام بعد
پس از انتخاب صریح PostgreSQL و Supabase اختصاصی ملکینو، اجرای بازبینی‌شدهٔ migrationها، provisioning کنترل‌شده و آزمون integration/E2E و RLS واقعی را انجام دهید. جزئیات در اسناد هم‌مسیر آمده‌اند.
